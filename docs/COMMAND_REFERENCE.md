# FFS viewer command reference

Generated by [`scripts/extract_commands.py`](../scripts/extract_commands.py) from
[`reference/fastfuncstuff/fastfuncstuff/viewer/vocab.py`](../reference/fastfuncstuff/fastfuncstuff/viewer/vocab.py) and the `Aspect` enum in
[`reference/fastfuncstuff/fastfuncstuff/viewer/commands.py`](../reference/fastfuncstuff/fastfuncstuff/viewer/commands.py). **Do not edit by hand** -- rerun the
script. The read-only clone under `reference/` is the source of truth; file:line
citations below are lines in that clone.

Each command is a frozen dataclass registered on the FFS command bus. Arguments
are positional on a script line in the order listed; `--` means the command takes
none. `major` marks commands a replay may pause on (data loads, fits, seeds).
`aspects` is what a command invalidates, so the UI can skip irrelevant repaints.

## Categories

| Category | Definition | What a command in it changes |
|---|---|---|
| `source` | Data loaded, reloaded, removed, re-stacked or saved. | Which datasets exist and where they sit in the stack. |
| `analysis` | What is computed from the data: modes, DENOISE, paint, committed surface edits, ROI/cluster/derive producers, InstaCorr's seed. | A layer's values, a mesh's geometry, or what the active mode fits. |
| `display` | How existing data is drawn: colour, range, threshold, layer appearance and stack order, sub-brick shown, surface shape/depth/map/folding, window contents, theme. | Pixels only -- no voxel, mesh or fit changes. |
| `navigation` | Where and when you are looking: crosshair, time index, viewport lifecycle, zoom/pan/tilt/lock, parked slices, panel choice. | Nothing in the data; the view and the clock move. |

Assignments that could reasonably be argued the other way are listed below
rather than hidden in the code:

| Command | Why it is where it is |
|---|---|
| `SELECT_LAYER` | display -- aims the controls (editing) but also decides what a soloed window draws; display. |
| `SET_ATLAS` | display -- changes names in the readout and the annot map, never a voxel; display. |
| `SET_LAYER_FOLLOWS` | display -- same transform question as SET\_LAYER\_XFORM; display. |
| `SET_LAYER_ROI` | display -- also changes what an ROI can be used for, but its visible effect is colouring; display. |
| `SET_LAYER_XFORM` | display -- geometry, but the voxels never move -- it is where they are drawn, so display. |
| `SET_SEED` | analysis -- navigation-like (it names a voxel) but it is InstaCorr's input, so analysis. |
| `SET_TIME_LINKED` | display -- a layer setting, but it decides what the clock does to it; navigation. |
| `SET_VIEW_DETREND` | display -- projects drift out, but only into the carpet/matrix picture; display. |
| `SET_VIEW_ROIS` | display -- picks a data source, but only for the matrix window's nodes; display. |
| `SET_VIEW_STRIP` | navigation -- draws extra slices, but it is window geometry (which slices); navigation. |
| `USE_MESH` | source -- reads no file, but selects which loaded mesh is the hemisphere's data; source. |

## Script syntax

A recorded session is one command per line: the name, then the positional
arguments in the order above, encoded as plain scalars. Booleans are `1`/`0`,
empty optionals are `-`, strings with spaces are quoted (`shlex` rules), `#`
starts a comment. Example: `SET_IJK 32 40 25`, `SET_THRESHOLD L2 2.5`.
Parsing lives in `viewer/commands.py` (`parse_script`, `_build`); recording
collapses runs of the same non-major command aimed at the same target.
